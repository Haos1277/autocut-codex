# autocut — сборка ролика из записи

## Среда Codex

Перед запуском проверь отдельное Python-окружение в папке этого скилла.
Если `.venv` отсутствует, сначала создай его и установи зависимости из
`requirements.txt`; не используй системный Python для установки пакетов.
Перейди в корень папки скилла (где SKILL.md, не внутрь scripts).
Все команды `python` ниже означают `.venv/bin/python` на macOS/Linux
или `.venv/Scripts/python.exe` на Windows. Пример для macOS/Linux:

```
.venv/bin/python scripts/init_project.py <папка-проекта> --source <запись>
```

Не требуй от пользователя вручную активировать окружение в терминале.

Скилл собирает ролик из записи говорящего человека: режет паузы
и переснятые дубли, чинит звук, ставит субтитры, раскладывает кадр
и рисует вставки. Видеоредактор не нужен. Эта упаковка проверена на macOS;
на Windows и Linux зависимости и рендер нужно проверить на целевой машине.

Всё основное работает на своей машине и ничего не стоит. Генерация
картинок и футажей — отдельный уровень в конце этого файла: она требует
либо ключа к платному сервису, либо мощной видеокарты, и без неё скилл
полноценен.

**Редакторский этап выполняет ассистент, не скрипт поиска слов.**
По полной расшифровке предложи смысловой отбор и связную историю:
сильное начало, необходимый контекст, развитие и вывод. Решения об
удалении мыслей и перестановке фрагментов согласуются до резки.
Если заказана только техническая чистка, сохрани содержание и порядок.

## Шаг 0. Интейк — обязательно, до любого кода

Если в папке проекта нет `style.json`, **сначала спроси** — по одному
вопросу за раз, не списком:

1. Что за материал: интервью, монолог на камеру, подкаст, экранная запись?
2. На каком языке говорят?
3. Какая длина на выходе: как получится или надо уложиться в лимит?
4. Насколько плотно резать? Три варианта:
   - бережно — только явные провалы, паузы до 0,6 с;
   - обычно — паузы до 0,35 с, слова-паразиты долой;
   - плотно — паузы до 0,2 с, режем всё лишнее.
5. Есть слова, которые режем всегда? (свой список паразитов)
6. Есть слова, которые НЕ трогаем ни при каких условиях? (термины,
   названия, имена)
7. Повторные дубли выбрасывать автоматически или показывать список
   и ждать решения?
8. Нужны ли визуальные вставки: без вставок, иллюстрации, текстовые
   карточки или оба вида?
9. Как часто они должны появляться: редко, умеренно, часто или не больше
   заданного количества за ролик?
10. Где их можно показывать: на весь экран, рядом с ведущим (`70/30` или
    `50/50`), поверх кадра — или предложить после проверки композиции?
11. Какой визуальный стиль использовать: цвета, настроение, реализм или
    иллюстрация, шрифты, логотип и примеры оформления?
12. Можно ли отправлять промпты и предоставленные изображения во
    встроенную генерацию изображений Codex? Объясни, что эти данные
    обрабатываются внешним сервисом.

**Не придумывай ответы за человека и не начинай резать, пока не спросил.**
Ответы сложи в `style.json` в папке проекта и покажи их одним списком —
пусть подтвердит.

Это первое обязательное согласование — **визуальный бриф до монтажа**.
Для смыслового монтажа также уточни аудиторию, основную задачу ролика,
формат (одна история или несколько самостоятельных роликов), целевую
длину и допустимость перестановок. Уже полученные ответы не спрашивай
повторно; никакого отдельного согласия на выдумывание фактов это не даёт.
Даже если `style.json` уже существует, при первом запросе вставок для
конкретного ролика уточни их тип, частоту и стиль. До подтверждения брифа
не запускай анализ, резку, генерацию изображений или рендер.

**Если у человека есть готовые ролики его канала — снимай настройки с них,
а не выдумывай.** Попроси 3-5 уже смонтированных выпусков (не сырьё:
нам нужны его привычки монтажа) и запусти:

```
python scripts/learn_style.py <папка-с-роликами> <проект> ru
```

Скрипт померит его типичную паузу, темп речи, сколько слов-паразитов он
сам оставляет и как часто меняет план. Из этого получатся настройки в его
манере. **Покажи цифры автору и спроси, согласен ли он** — замер это
предложение, а не приговор.

## Шаг 1. Завести проект

```
python scripts/init_project.py <папка-проекта> --source <запись>
```

Создаёт разложенные папки и памятку: `input/` для исходников,
`inserts/` для вставок, `work/` для служебного, `out/` для результата.
Не раскладывать файлы вручную по своему усмотрению — остальные скрипты

## Порядок работы

Все скрипты в `scripts/`. Запускать из корня скилла, Python 3.10+,
через интерпретатор окружения, указанный выше.

```
python scripts/prepare.py    <исходник> <проект>
python scripts/transcribe.py <проект>/work/audio.wav ru
```

Теперь выполни **смысловой разбор и сценарий** ниже. Это не команда Python.
При смысловом монтаже до согласования сценария не переходи к резке.
Следующие команды — техническая чистка, а не автоматический исполнитель
редакторского сценария:

```
python scripts/speech_map.py <проект>/work/audio.wav
python scripts/rough_cut.py  <исходник> <проект>
python scripts/rough_cut.py  <исходник> <проект> --render
python scripts/check_output.py <проект> ru
python scripts/clean_audio.py <проект>/out/rough.mp4 <проект> --render
python scripts/subtitles.py <проект>/out/clean.mp4 <проект> --plan plan.json --burn
```

Ключ `--plan` при субтитрах ОБЯЗАТЕЛЕН, если в ролике есть вставки:
без него субтитры лягут прямо на карточки и обе надписи станут
нечитаемыми.

Звук — последним шагом, уже по смонтированному. `clean_audio.py` без
`--render` печатает диагноз и ничего не трогает.

`rough_cut.py` без `--render` **ничего не рендерит** — только печатает,
что собрался вырезать. Это специально: сначала показать план человеку,
получить «да», и только потом тратить время на кодирование.

## Смысловой разбор и сценарий — после полной расшифровки, до резки

Для запросов о ключевых моментах, хуках, сокращении по смыслу и сборке
истории прочитай [references/story-editing.md](references/story-editing.md)
целиком. Сначала прочитай всю расшифровку, включая конец; при большом
объёме читай последовательно частями с картой покрытия. Затем создай
`work/story-outline.md`: тема и тезис, смысловые блоки, кандидаты в хуки
с контекстом, связный сценарий с исходными таймкодами и обоснованием.
Ключевые слова — навигация по теме, не критерий ценности фрагмента.

Покажи сценарий и получи подтверждение перед смысловой резкой. Не
подменяй историю набором эффектных цитат. Отметь непрочитанные интервалы,
неясные места и отсутствие доступа к видео/звуку; не заявляй полный
анализ или проверенную склейку без соответствующей проверки.

## План вставок — после согласования сценария

Если согласован режим без вставок, этот этап пропускается: отдельный
пустой план и его подтверждение не нужны. Согласование сценария и
проверка черновика остаются обязательными для смыслового монтажа.

После расшифровки и до генерации материалов составь таблицу:

```
Время | Фраза | Тип вставки | Содержание | Раскладка | Длительность
```

Для каждой иллюстрации рядом покажи точный промпт. Для каждой текстовой
карточки покажи точный заголовок, список, число, цитату или код. Это
отдельное обязательное согласование — **план вставок**. Для технической
чистки без смыслового отбора этот этап следует сразу после расшифровки.

До явного подтверждения плана не генерируй изображения, не запускай
`cards.py`, не добавляй вставки в `plan.json` и не начинай финальный
рендер. Если человек исправил формулировку или место появления, сначала
обнови таблицу и снова покажи изменённые строки.

## Правила, которые важнее кода

**Границы кусков — по громкости, не по расшифровке.** Whisper на паузах
врёт на сотни миллисекунд и растягивает слово на соседнюю тишину. Если
резать по его таймкодам, слова обрубаются. Огибающая громкости показывает
край слова точно. Текст из расшифровки только раскладывается по уже
готовым кускам.

**Порог тишины — от самой записи, не абсолютный.** Считается между
собственной тишиной записи и её пиками. Поэтому одинаково работает
на тихой записи с телефона и на громкой студийной.

**Запинки автоматически не убираются — говорить об этом прямо.** Whisper
не записывает тянущиеся «эээ», «ммм» и часть «ну»: он выбрасывает их как
шум. В расшифровке их нет, а по громкости они речь — значит их не берёт
ни поиск по тексту, ни срезание паузы. Замер на сырой трёхминутной
записи: 343 слова и ровно один паразит в тексте. Основную пользу даёт
срезание пауз (там же — 40 секунд из 42). Если заказчик ждёт, что уйдут
именно запинки, предупредить заранее.

**Слово-паразит режем только обособленное.** Если перед ним и после него
нет хотя бы 0,08 с зазора, шов придётся на середину слитной фразы и это
будет слышно. Лучше оставить лишнее «ну», чем сделать дырку в речи.

**Приёмка обязательна.** `check_output.py` меряет уровень звука в каждом
вырезанном окне. Если в окне, помеченном как пауза, была речь — значит
рез пришёлся на слово, это брак. Разночтения расшифровки при этом
ни о чём не говорят: Whisper на одном и том же звуке дважды слышит
по-разному, и «пропавшее слово» в его отчёте почти всегда мнимое.

**После правки настроек рендерить заново с нуля.** Не подклеивать куски
к прошлому результату.

**Со звуком чинить только сломанное.** Глушить шум там, где его почти нет,
значит съесть воздух в голосе. Скрипт сам решает по замеру — не заставляй
его давить шум «на всякий случай».

**Громкость ставить усилением с лимитером, а не `loudnorm`.** Тот в один
проход работает как компрессор: подтягивает тихие места, а тихие места
это и есть шум. Замер: запас упал с 30 до 27 дБ, и до цели всё равно
не дотянуло. У горячих записей (пик 0 дБ — обычное дело для телефона)
линейный режим `loudnorm` недоступен, он молча уходит в динамический.

**Подгонку тембра под эталон делать только по похожей записи.** Эквалайзер
не различает голос и шипение: подъём верха вытягивает и то, и другое.
Если правка выходит больше 4 дБ — записи слишком разные, толку не будет.

**Субтитры мерить скоростью чтения, а не длиной строки.** Комфортно
до 20 знаков в секунду, 25 — предел. Реплику нельзя «подержать подольше»:
она живёт до первого слова следующей. Поэтому слишком быструю реплику
можно только склеить с соседней — но НЕ через точку: две фразы в одной
реплике читаются хуже, чем одна чуть быстрая. Скрипт печатает скорость
чтения и число слишком быстрых реплик — это и есть показатель качества.

**Сколько символов влезает в строку — считать, а не назначать.** Скрипт
берёт ширину кадра и кегль и считает сам. Обрезанный краем кадра текст
рождается ровно из назначенного наугад лимита.

**Вставки рисует `cards.py`.** Четыре вида: заголовок с подписью, список,
крупное число, блок кода. Кегль подбирается под размер карточки сам —
текста, вылезающего за края, не бывает по построению. Фон по умолчанию
прозрачный: статичная карточка сохраняется как RGBA PNG. С `--anim` рядом
кладётся ProRes 4444 `.mov` с альфа-каналом, где содержимое появляется
по частям. Явный цвет `"bg": "#101010"` создаёт непрозрачный фон.

Размер карточки задавать под ту полосу, куда она пойдёт: для `70/30`
это 1080x576, для `50/50` — 1080x960, для `full` — весь кадр. Иначе
`compose.py` обрежет лишнее по краям.

**Раскладку выбирать по содержанию куска, а не по кругу.** Три раскладки
чередуются: `70/30` (ведущий сверху 70%, вставка узкой полосой снизу),
`50/50` (пополам, годится для сравнений «было — стало»), `full` (вставка
на весь кадр, 2-4 с, под демонстрацию или ударную фразу). Плюс `over` —
вставка накладывается поверх, кадр не делится. Одна и та же раскладка
два раза подряд — брак, `compose.py` на это ругается.

**Прежде чем делить кадр — проверить, можно ли.** `layout_probe.py`
смотрит, где в кадре самое живое место, и говорит для каждой раскладки:
обрезать, вписать целиком или только накладывать вставку поверх. Если
человек занимает кадр глубоко (типовой селфи-кадр: лицо в середине,
снизу микрофон и руки), деление отрежет ему рот. Не спорить с вердиктом
«поверх» — он ровно про этот случай.

## Визуальные вставки: ImageGen и точный текст

Есть два разных маршрута, их нельзя смешивать.

### Иллюстрации без текста — встроенный ImageGen Codex

Для сцен, предметов, фонов и визуальных метафор используй встроенную
генерацию изображений Codex. `scripts/gen_image.py` в Codex-процессе не
используй: он оставлен только как резерв для других сред.

Сохраняй полученные изображения в `<проект>/inserts/` и только после
утверждения добавляй пути в `plan.json`. Генерируй изображение сразу под
согласованную раскладку: `1080x576` для `70/30`, `1080x960` для `50/50`
или размер всего кадра для `full`.

**Генерация отправляет данные наружу.** Промпт и приложенные изображения
обрабатываются внешним сервисом. Согласие на это входит в первоначальный
визуальный бриф. Не отправляй кадры с лицами или чужие материалы без
явного разрешения.

Не проси ImageGen рисовать заголовки, списки, цифры, цитаты или код:
генеративный текст может исказиться.

### Точный текст — `cards.py`

Заголовки, списки, крупные числа, цитаты и блоки кода создавай локально
через `cards.py`. Текст для каждой карточки должен дословно совпадать с
утверждённым планом вставок.

По умолчанию `cards.py` создаёт прозрачный RGBA PNG, а с `--anim` —
прозрачный ProRes 4444 `.mov`. Для текста поверх ведущего используй
раскладку `over`: прозрачные области покажут исходное видео, без видимого
прямоугольника карточки. Если нужен отдельный слайд с однотонным фоном,
задай цвет через `bg` явно.

Текущий `compose.py` принимает только одну вставку в сегменте. Поэтому он
умеет наложить прозрачную карточку поверх ведущего, но ещё не умеет в том
же сегменте сначала показать ImageGen-изображение и поверх него наложить
вторую текстовую карточку. Не обещай такое объединение без отдельного
расширения `compose.py` и не запекай точный текст в генеративную картинку.

**Сначала одна картинка, потом партия.** Покажи первый результат и получи
подтверждение визуального направления. Только после этого создавай
остальные утверждённые изображения.

Осечки, которые повторяются:

- **перекрытие наоборот** — просите «предмет перед человеком»,
  получаете наоборот;
- **серый фон** вместо описанной среды — описывать фон отдельной фразой;
- **дописанные подписи** и водяные знаки — запрещать прямым текстом;
- **самовольный неон** — запрещать, если не нужен;
- **отказ на лицах** — персонажа сначала создать отдельно, без
  фотографии-образца, дальше вести его этой картинкой;
- **игнор слов про телосложение** — пока в образце нет фигуры с такими
  пропорциями, слова «коренастый», «плотный» не действуют.

Описывать надо свет, камеру и материал, а не только предмет.
«Клавиатура» даст сток. «Руки на механической клавиатуре, единственный
источник света — монитор сбоку, крупный план, видна текстура кожи» —
даст кадр.

Когда брать: сложная анимация, которую не нарисовать карточками.
Для обычных вставок хватает `cards.py` — он быстрее реального времени
и ничего не требует.

### Видео-перебивки

```
python scripts/setup_ltx.py
```

Проверяет, потянет ли машина локальную генерацию, и ничего не качает
без разрешения: весов там на 37 ГБ.

Правила перебивки, не зависящие от движка:

- **частоту кадров брать как у ведущего.** Перебивка на 24 в ролике
  на 30 заметна как рывок;
- **3-6 секунд**, длиннее — зритель забывает, кого слушал;
- **тёмная, «как снято»** — вставка должна выглядеть съёмкой, иначе
  выпадает из ролика;
- **звук вырезать** — модели генерируют его вместе с картинкой, под
  говорящей головой он не нужен никогда;
- **крупные лица и текст в кадре не заказывать** — на них ломаются все
  доступные модели. Руки, предметы, фактуры, обстановка — заказывать.

## Когда скилл не поможет

- Несколько говорящих с перебиванием — карта речи их не разделяет.
- Музыка или шум громче речи — порог тишины поплывёт.
- Материал, где паузы несут смысл (драма, стендап) — резать по паузам
  там нельзя, отговори человека.
- Плохо записанный звук с сильным эхом — сначала лечить звук, потом резать.
