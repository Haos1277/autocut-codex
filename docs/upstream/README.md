# autocut-skill

**[English version](README.en.md)**

Скилл для Claude Code: собирает ролик из записи говорящего человека.
Режет паузы и повторные дубли, чинит звук, ставит субтитры, раскладывает
кадр и рисует вставки. Видеоредактор не нужен.

Работает на Windows, macOS и Linux.

## Что он делает

- **Режет.** Находит по звуку, где человек говорит, а где молчит.
  Сокращает паузы, вырезает слова-паразиты, находит переговорённые
  фразы и оставляет последний дубль.
- **Проверяет за собой.** Меряет уровень звука в каждом вырезанном окне
  и говорит, если рез пришёлся на слово.
- **Чинит звук.** Гул, срезанные пики, шум, громкость. Умеет подтянуть
  тембр под запись, которая вам нравится.
- **Ставит субтитры** вашим стилем: .ass со стилем и .srt отдельно,
  с впечатыванием в картинку и подсветкой произносимого слова.
- **Раскладывает кадр.** Сначала проверяет, можно ли его вообще делить,
  потом собирает: ведущий и вставка в пропорции 70/30 или пополам,
  вставка на весь кадр, вставка поверх кадра.
- **Рисует вставки:** заголовок, список, крупное число, блок кода —
  с появлением содержимого по частям.
- **Снимает ваши настройки** с ваших же выпущенных роликов, чтобы
  не выдумывать их анкетой.
- **Генерирует картинки и футажи** — если у вас есть свой ключ
  к сервису или мощная видеокарта. Без этого всё остальное работает.

## Чего он не делает

- **Не выбирает, что оставить в ролике.** Это редакторская работа.
  Скилл убирает мусор, а не решает, какая мысль лишняя. Замер на живом
  материале: из 3 минут сырья скилл сделал 2:15, человек руками — 0:52.
- Не убирает запинки (см. ниже, там объяснено почему).
- Не делает цветокоррекцию и музыку.
- Не синтезирует голос.

Не подойдёт, если: в кадре несколько человек перебивают друг друга;
музыка громче речи; паузы несут смысл (стендап, драма).

### Про запинки — этого ждут чаще всего

Убирать их скилл не умеет, и вот почему. Тянущиеся
«эээ», «ммм» и часть «ну» не попадают в расшифровку — распознавание
выбрасывает их как шум, — а по громкости они речь. Их не находит ни
поиск по словам, ни срезание пауз. На реальной трёхминутной записи
в расшифровке оказалось 343 слова и один паразит. Основную пользу даёт
срезание пауз: там же 40 секунд из 42.

## Что нужно

- **Claude Code** — [инструкция по установке](https://docs.claude.com/en/docs/claude-code)
- **Python 3.10+**
- **ffmpeg** в PATH
- Видеокарта **не нужна**, всё считается на процессоре

Расшифровка на процессоре идёт примерно в полтора-два раза медленнее
реального времени: минута записи — полторы-две минуты ожидания.
На слабой машине берите модель поменьше (см. ниже).

## Установка

**1. ffmpeg**

```bash
# macOS
brew install ffmpeg

# Windows
winget install Gyan.FFmpeg

# Linux
sudo apt install ffmpeg
```

Проверить: `ffmpeg -version` должен что-то ответить.

**2. Распаковать архив со скиллом**

Распакуйте `autocut-skill.zip` в удобную папку и перейдите в неё.

**3. Python-пакеты**

```bash
python -m venv .venv

# macOS / Linux
source .venv/bin/activate
# Windows
.venv\Scripts\activate

pip install -r requirements.txt
```

**4. Подключить к Claude Code**

Скопируйте папку `autocut` в `.claude/skills/` вашего проекта:

```bash
# macOS / Linux
mkdir -p ~/.claude/skills && cp -r autocut ~/.claude/skills/

# Windows PowerShell
New-Item -ItemType Directory -Force "$HOME\.claude\skills"
Copy-Item -Recurse autocut "$HOME\.claude\skills\"
```

Перезапустите Claude Code. Скажите «сделай черновой монтаж этой записи»
и киньте файл — скилл подхватится сам.

## Первый запуск

Заведите проект — он создаст папки и памятку, что куда класть:

```bash
python autocut/scripts/init_project.py мой-проект --source запись.mp4
```

| Папка | Что в ней |
|---|---|
| `input/` | исходные записи, как сняли |
| `inserts/` | карточки и картинки для вставок |
| `work/` | служебное: расшифровки, планы. Можно удалять |
| `out/` | результат |

Скилл сначала задаст несколько вопросов: что за материал, на каком языке,
насколько плотно резать, какие слова не трогать. Ответы сохранятся
в `style.json` рядом с проектом, второй раз спрашивать не будет.

Это сделано намеренно: настройки реза у всех разные, и подставлять
чужие по умолчанию — верный способ испортить материал.

Если у вас уже есть выпущенные ролики, настройки можно не выдумывать,
а снять с них:

```bash
python autocut/scripts/learn_style.py папка-с-роликами проект ru
```

Скрипт померит вашу типичную паузу, темп речи, сколько слов-паразитов
вы оставляете сами и как часто меняете план — и предложит настройки
в вашей манере. Нужны именно смонтированные выпуски, а не сырьё:
мы снимаем привычки монтажа, а не привычки речи.

## Как это работает руками, без Claude Code

```bash
python autocut/scripts/prepare.py    запись.mp4 проект
python autocut/scripts/transcribe.py проект/work/audio.wav ru
python autocut/scripts/speech_map.py проект/work/audio.wav
python autocut/scripts/rough_cut.py  запись.mp4 проект
```

Последняя команда **ничего не рендерит** — печатает план: сколько
и чего вырежет. Посмотрели, устраивает — запускаете с `--render`:

```bash
python autocut/scripts/rough_cut.py запись.mp4 проект --render
python autocut/scripts/check_output.py проект ru
```

Результат — `проект/out/rough.mp4`.

### Звук

Последним шагом — починка звука:

```bash
python autocut/scripts/clean_audio.py проект/out/rough.mp4 проект
```

Печатает диагноз: сколько шума, есть ли клиппинг, какая громкость.
Файл не трогает, пока не добавите `--render`.

Чинит только то, что действительно сломано: срезает гул, восстанавливает
срезанные пики, глушит шум — но не трогает шум там, где его почти нет,
иначе из голоса уходит воздух. Громкость выводит к нужному уровню.

```
--lufs -14      целевая громкость (-14 для сети, -16 тише, -23 телевещание)
--like файл     подогнать тембр под звук, который вам нравится
--no-denoise    не трогать шум
```

`--like` сравнивает форму спектра вашей записи с эталоном по полосам
и подтягивает вашу к нему. Работает, когда записи сопоставимы: эквалайзер
не различает голос и шипение, поэтому подъём верха вытянет и то, и другое.
Если правка выходит больше 4 дБ, скрипт об этом скажет.

Если в исходнике есть видео, картинка копируется без перекодирования.

### Субтитры

```bash
python autocut/scripts/subtitles.py проект/out/clean.mp4 проект
```

Собирает субтитры из пословных таймкодов и пишет два файла: `subs.ass`
со стилем и `subs.srt` для загрузки куда угодно. С `--burn` впечатывает
в видео.

Речь разбивается на реплики по знакам препинания и паузам, а не по числу
символов наугад. Переносы строк ставятся после запятых и точек, чтобы
строка не обрывалась посреди словосочетания.

```
--font Arial        шрифт (должен стоять в системе)
--size 64           высота букв в пикселях
--color #FFFFFF     цвет текста
--outline #000000   цвет обводки, --outline-w толщина
--shadow 2          мягкая тень, 0 отключить
--pos bottom        bottom | top | center
--margin 220        отступ от края кадра
--caps              КАПСОМ
--karaoke           подсвечивать произносимое слово, --hl задаёт цвет
--burn              впечатать в видео
```

Отступ по умолчанию — 11% высоты кадра: у вертикального видео нижнюю
часть перекрывает интерфейс площадки, и текст туда ставить нельзя.

Скрипт печатает **скорость чтения** — главный показатель качества
субтитров. Комфортно до 20 знаков в секунду, 25 предел. Если реплик
сверх нормы много, уменьшите кегль: в строку влезет больше, и реплики
станут длиннее по времени.

### Карточки-вставки

Описываете вставки json-файлом и рисуете:

```bash
python autocut/scripts/cards.py cards.json cards --anim
```

```json
{
 "style": {"bg": "#101010", "fg": "#F2F2F2", "accent": "#4C8BF5"},
 "cards": [
  {"name": "a", "size": [1080, 576], "type": "list",
   "title": "Что он делает", "items": ["режет паузы", "ставит субтитры"]},
  {"name": "b", "size": [1080, 1920], "type": "stat",
   "value": "24%", "caption": "тишины в записи"}
 ]
}
```

Виды карточек: `text` (заголовок и подпись), `list` (заголовок и пункты),
`stat` (крупное число с подписью), `code` (блок кода моноширинным).

Стиль задаёте вы: фон, цвет текста, акцент, шрифт, выравнивание, отступы.
Значения по умолчанию нейтральные — под свой канал их нужно поменять.

**Кегль подбирается автоматически** под размер карточки. Текст, вылезающий
за края, — самая частая поломка вставок, и здесь она исключена: скрипт
уменьшает шрифт, пока содержимое не влезет.

С `--anim` рядом с png появляется короткое видео: содержимое всплывает
по частям за полсекунды, дальше кадр стоит. Длина берётся из `"dur"`.

Размер карточки задавайте под ту полосу, куда она пойдёт: для `70/30`
это 1080x576, для `50/50` — 1080x960, для `full` — весь кадр.

Шрифт ищется в системе (Arial, Helvetica, DejaVu). Свой указывается
ключом `"font"`. Скрипт проверяет, есть ли в шрифте кириллица, и
предупреждает: Pillow об отсутствующих буквах молчит и рисует пустые
квадраты.

### Раскладка кадра и вставки

Одна раскладка на весь ролик выглядит монотонно, поэтому их чередуют:

| Раскладка | Что в кадре |
|---|---|
| `70/30` | ведущий сверху 70% высоты, вставка узкой полосой снизу |
| `50/50` | пополам — годится для сравнений «было — стало» |
| `full` | вставка на весь кадр, 2-4 секунды |
| `over` | вставка накладывается поверх, кадр не делится |
| `none` | только ведущий |

Сначала проверьте, можно ли вообще делить кадр:

```bash
python autocut/scripts/layout_probe.py запись.mp4
```

Скрипт смотрит, где в кадре самое живое место, и для каждой раскладки
говорит: обрезать, вписать целиком или только накладывать поверх. Если
человек занимает кадр глубоко — лицо в середине, снизу микрофон и руки, —
деление отрежет ему рот, и это единственный честный ответ.

Дальше опишите ролик планом `plan.json`:

```json
{
 "source": "out/clean.mp4",
 "segments": [
  {"start": 0.0, "end": 4.0,  "layout": "none"},
  {"start": 4.0, "end": 7.5,  "layout": "70/30", "insert": "cards/a.png"},
  {"start": 7.5, "end": 10.5, "layout": "full",  "insert": "cards/b.png"}
 ]
}
```

```bash
python autocut/scripts/compose.py plan.json
python autocut/scripts/compose.py plan.json --render
```

Без `--render` скрипт разбирает план и печатает замечания: раскладка два
раза подряд, слишком долгий фуллскрин, дыра между кусками, пропавший файл
вставки, кусок дольше пяти секунд без смены картинки.

Как подать ведущего в его полосу, задаёт `"mode"`: `crop` обрезать (крупно,
но низ кадра уедет) или `fit` вписать целиком (лицо целое, но мелкое).
При вписывании пустые поля по бокам заполняются размытой копией кадра —
однотонные полосы выглядят недоделанно. Вернуть однотон: `"fill": "color"`
и `"bg": "#000000"`.

### Настройки реза

```
--pause 0.35      сколько паузы оставлять на стыке фраз, секунды
--edge 0.25       сколько тишины оставлять в начале и в конце
--keep-fillers    не трогать слова-паразиты
--keep-repeats    не выбрасывать повторные дубли
--repeat 0.90     порог похожести дублей, 0..1
```

### Модель распознавания

По умолчанию `large-v3-turbo` — точная, но качает ~1,5 ГБ при первом
запуске. Если машина слабая:

```bash
python autocut/scripts/transcribe.py проект/work/audio.wav ru small
```

`small` или `base` работают в несколько раз быстрее, но чаще ошибаются
в терминах и именах.

## Почему рез по громкости, а не по расшифровке

Главный подводный камень автомонтажа: Whisper на границах пауз
ошибается на сотни миллисекунд и растягивает слово на соседнюю тишину.
Мы поймали слово длиной 1,76 с, которое на самом деле звучало вдвое
меньше — остальное было паузой. Режь по таким таймкодам, и слова
начнут обрубаться.

Поэтому границы кусков берутся из огибающей громкости самого звука,
а расшифровка нужна только чтобы понимать, что в куске сказано.

Проверка тоже идёт по звуку, а не по тексту: скрипт меряет уровень
в каждом вырезанном окне. Была там речь — значит рез пришёлся на слово.
Сравнивать расшифровки до и после бесполезно: Whisper на одном и том же
звуке дважды слышит по-разному, и «пропавшее слово» почти всегда мнимое.

## Генерация картинок и футажей

Это единственная часть, которая требует денег или мощного железа.
Без неё скилл полноценен: вставки собираются карточками.

**Картинки** — по вашему ключу к картиночному сервису:

```bash
python autocut/scripts/gen_image.py --prompt "..." --out inserts/a.png --dry
```

`--dry` показывает, что ушло бы наружу, и ничего не отправляет.
Ключ берётся из переменной окружения или из `.env` рядом с проектом,
нигде не печатается и в архив со скиллом не попадает.

**Видео-перебивки** — проверьте, потянет ли машина:

```bash
python autocut/scripts/setup_ltx.py
```

Скрипт ничего не качает: там 37 ГБ весов и отдельная программа,
это решение человека. На маке локальной генерации нет вовсе —
только облако.

**Моушен-графика на Remotion** — когда карточек не хватает:

```bash
python autocut/scripts/setup_remotion.py мой-проект --scaffold
```

**Внимание, лицензия:** Remotion бесплатен для физлиц и компаний
до 3 сотрудников, остальным нужна платная Company License. Скилл его
не ставит и не может решить это за вас. Всё остальное здесь свободно
и таких требований не имеет.

## Приватность

Скилл работает полностью на вашей машине. Ваши записи никуда не
отправляются. Единственное обращение в сеть — скачивание весов модели
распознавания при первом запуске.

Это верно для всего, что описано выше. Отдельное дополнение, которое
добавляет генерацию картинок и футажей, работает иначе: оно отправляет
ваш запрос и приложенные картинки на сервер владельца модели. Если
поставите его — учитывайте это. Без него автомонтаж работает целиком
на вашей машине.
